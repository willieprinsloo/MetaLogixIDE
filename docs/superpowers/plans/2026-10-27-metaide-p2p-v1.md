# metaIDE P2P Fleet v1 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v1 of metaIDE P2P: from any running metaIDE, see your other machines in a Machines sidebar, open a project on one of them, and attach to its Claude shells and files over a WebRTC data channel brokered through MetaConnect.

**Architecture:** One artefact (the existing metaIDE Electron app) acts as both client and server. A new in-tree `src/main/p2p/` module brokers through MetaConnect over TCP+TLS, mints a session, and opens a WebRTC data channel to the peer. RTCPeerConnection lives in a hidden background BrowserWindow (because `RTCPeerConnection` is a renderer-process API in Electron); main-process code talks to that worker via IPC. A thin RPC layer dispatches `projects.*`, `shells.*`, `fs.*`, `claude.*` calls into the already-existing main-process IPC handlers — no business logic is duplicated. A one-line change in the `metaconnect` repo adds the `TypeMetaIDE` signaling route.

**Tech Stack:** TypeScript, Electron (existing), node-pty (existing), better-sqlite3 (existing), WebRTC (via hidden BrowserWindow), `@noble/curves` + `@noble/ciphers` for Noise XX, Go (one small PR in metaconnect).

**Spec:** `docs/superpowers/specs/2026-10-26-metaide-p2p-design.md`

## Global Constraints

- Default relay URL: `signal.metalogix.solutions` / `165.232.97.123`. User override in Settings → P2P.
- Signaling wire form: adjacently-tagged `{"type":"<snake_case>","data":{...}}`, length-prefixed with a 4-byte big-endian u32, over TLS TCP. Matches `mrsignal.Envelope` + `mr-relay` framing exactly.
- MetaConnect protocol envelope type for every IDE signaling frame: `TypeMetaIDE = "metaide"` (new constant, added in Task 1).
- Inner signaling types reused verbatim from `mrsignal`: `register`, `session_request`, `session_invite`, `session_granted`, `session_denied`, `offer`, `answer`, `ice_candidate`, `session_close`, `assign_code`.
- Device identity: Ed25519 keypair stored at `~/.metaide/device.key` with mode `0600`. MetaConnect agent token stored at `~/.metaide/agent.token` with mode `0600`.
- Secret fields (`secret`, `token`, raw PTY bytes) never written to logs. Wrap each in a `Secret<T>` type whose `toString()` returns `"<redacted>"`.
- Pre-RPC: every data channel runs a Noise XX handshake using the device Ed25519 key as the static key before any application frame is passed. If Noise fails, close the data channel and surface a `trust_failed` error.
- Maximum RPC frame size: 1 MiB. Oversize frames close the channel with `frame_too_large`.
- All new SQL changes are additive migrations numbered `003_p2p.sql` upward.
- Tests: Vitest for the Electron main-process modules (already in the repo); Go `testing` for the metaconnect PR.
- Node ≥ 20.
- No feature flag — the P2P panel in Settings is disabled until the user opts into pairing, which is the gate.

## Review Focus

The five inputs/failure modes the spec implies but no task's happy-path test exercises; each has a test added in the owning task.

1. **Peer disconnects mid-shell** — the serving side's PTY must keep running; the client's shell tab must show "Reconnecting…" and resume with buffered scrollback on reattach. Owner: Task 7 (hub) + Task 11 (remoteShellBridge).
2. **Relay flaps / unreachable** — `mcClient` must reconnect with exponential backoff + jitter and not spin a tight loop while the relay is down. Owner: Task 3 (mcClient).
3. **Oversized or malformed frames from a peer** — `rpc` must bound frame size, reject invalid JSON, and never panic the main process. Owner: Task 6 (rpc).
4. **Path traversal in `fs.list` / `fs.read`** — remote FS methods must reject paths that escape their project root via `..`, symlinks, or absolute paths. Owner: Task 7 (hub).
5. **Clock skew / expired session token** — if the local clock is wrong, a valid session token could appear expired. Session-token TTL check must allow ±5 min skew; test both edges. Owner: Task 4 (session).
